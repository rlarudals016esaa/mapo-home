# 운영자 단독 개편 · 2026-10-06

사용자 사이트 코드·DB·공개 범위, 두 사이트 연동, 기존 자동화, 외부 푸시는 변경하지 않는다.

## 구현 범위

- 검토용 고객별 단일 조건, 전세/월세 필수, 월세 상한 검증, 선택 면적, 동네 최대 5개. 실제 사용자와 연결되지 않은 운영자 입력 자료임을 표시한다.
- 검토용 관심 매물과 개별 알림 설정. 미확인·조건 이탈·전체 중지·개별 중지·추적 불가 상태를 구분한다.
- 최신 사용자 model.ts의 순수 조건·알림 규칙을 review-policy.ts로 복사해 운영자 전용으로 사용한다. 사용자 파일은 수정하지 않았다. 후속 사용자 정책 변경 시 두 사본의 정책 검증을 함께 수행해야 한다.
- 조건 저장/수정은 알림을 생성하지 않는다. 수동 생성 API를 차단한다. 정상 자료 반영 시 신규 묶음, 관심 인하/혼합 변화/재진입만 내부 이벤트로 저장한다. 외부 발송 작업은 만들지 않는다.
- 기존 rules와 notices는 보관함으로 유지한다. 임의로 실고객이나 최신 조건으로 변환하지 않는다. 기존 저장 자료의 키를 삭제하지 않는 additive normalization을 사용한다.
- admin_event_batches는 자료 해시를 기본키로 한 영속적 내부 이벤트 기록이다. 상태 변경과 이벤트 삽입은 D1 batch 안에서 처리한다. revision 검사와 lastOperation 조건을 통해 충돌 시 이벤트가 남지 않게 한다. 발송 성공/실패나 외부 재시도 구현을 의미하지 않는다.
- 유사 후보는 현재 자료로 계산하며 원문·원본 행을 대조한다. 병합/삭제하지 않는다. 사용자 미리보기는 읽기 전용 정렬 함수를 재사용하며 넓은 화면에서 3열로 표시한다.
- 전체 수집 확인은 운영자가 수집 도구 완료 건수·실패 없음·마포구 범위를 확인하는 절차다. 파일 자체로 누락 없는 수집을 증명하지 않는다. 건수 불일치는 차단하고 30% 감소·유형 누락은 사유 검토를 요구한다. 같은 날 이전 시각 파일도 거절한다.
- 새 수집에는 원본 시트와 시각을 저장한다. 원문 확인·등록일을 구분해 상세 표시한다. 기존 DB 자료의 누락 메타데이터를 추정해 채우지 않는다.
- 반영별 신규·변경·미수집 ID 목록은 최근 30회 보관한다. 과거 건수 기록에서 상세 대상을 추정하지 않는다.
- 공공임대 메뉴는 연결 대기 화면이다. 마지막 실행/정상 확인 시각이나 스케줄러 상태를 조작하지 않는다. 정기 확인 자동화는 새로 만들지 않는다.

## 계속 제외되는 작업

실제 고객 조건·하트 조회, 공고 저장소 조회/수정, 사용자 API 응답 분리, 사용자 매물 전달, 웹 푸시 구독·발송, 일반 매물 자동 수집은 별도 후속 작업이다. INTEGRATION.md는 아직 미구현 계약이며 이 문서의 운영자 단독 변경을 실제 연동 완료로 해석하지 않는다.

## 검증

scripts/verify-operations.ts: 조건 제약, 실제 가격 쌍, 인하/혼합 변화, 관심 대상 한정, 이탈/재진입, 최초 무알림, 신규 묶음, 미확인 보존, 복수 가격 제외, 이전 자료 보존, 안정적 내부 이벤트 키, 수집 시각, 수집 급감, 실제 데이터·중복·정렬 검사.

scripts/verify-operations-api.mjs: 로컬 전용 API/DB 시나리오. 운영 배포의 사용자 데이터를 대상으로 실행하지 않는다.
