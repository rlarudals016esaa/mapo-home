# 마포홈 운영센터 연동 계약 — 제안 v1

현재 운영센터와 사용자 사이트는 서로 다른 Sites 프로젝트, 주소, D1이다. 이 문서는 후속 구현의 계약이며 아래 API는 아직 제공하지 않는다. 사용자 사이트 소스·공개 범위는 변경하지 않았다.

## 현재 동작

- 서버의 2026-10-06 기준 자료: SINGLE_20261006_130231.xlsx, Sheet1, 1,003행. 최초 상태는 기준 파일에서 제공하고 운영 작업부터 별도 D1에 저장한다.
- CSV(UTF-8)와 XLSX는 브라우저에서 읽고 서버에서 다시 구조·형식·날짜·중복을 검증한다. 원본 바이너리는 보관하지 않는다. 검증된 행과 검토 결과는 D1에 저장하며 확인 후 전체 스냅샷으로 반영한다.
- 목록, 조건, 내부 알림, 반영 이력, 운영 이력을 저장한다. 원문 ID가 없는 항목의 snapshot 키는 화면 행 식별용이며 외부 고유 매물 ID가 아니다. 동과 원문 링크를 추정하지 않는다.
- 등록 조건은 운영자가 입력한 별칭 기반 조건이다. 고객 사이트의 실제 사용자나 조건과 연결되지 않는다.
- 동일 사이트에서만 통하는 ChatGPT userId를 고객 식별자로 다른 사이트에 넘기지 않는다.
- 동일 revision에 대한 낙관적 잠금으로 다중 창의 덮어쓰기를 차단한다. 검증된 pending 자료만 commit 가능하다. POST는 동일 Origin만 허용한다.
- 현재 제한: 파일 5MB, 요청 4MB, 2,000행, 상태 1.9MB, 조건 50개, 알림 1,000건, 수집 이력 90회, 작업 이력 100건. 초과 시 저장하지 않고 오류를 반환한다. 장기 운영 전 행 단위 저장과 별도 이력 테이블로 전환할 것.

## 운영자 권한

Sites의 소유자 전용 비공개 접근 정책이 첫 경계다. 서버는 플랫폼 인증 헤더와 D1 administrators의 user_id를 매 요청 검사한다. OWNER_PRIVATE_BOOTSTRAP=true일 때 소유자만 접근 가능한 새 사이트의 첫 로그인 계정을 slot=1에 원자적으로 등록한다. 이후 다른 계정은 거절된다. 클라이언트는 권한을 지정할 수 없다. 로컬 테스트 계정은 로컬 D1에만 저장된다.

최초 실제 로그인 후 OWNER_PRIVATE_BOOTSTRAP=false로 배포하면 초기화 경로를 닫을 수 있다. 공개 범위 변경이나 다중 운영자 초대 전에 이 플래그를 끄고 명시적인 서버 역할 관리 및 계정 등록 절차를 구현해야 한다. 서비스를 공개로 바꾸어 초기화해서는 안 된다. 서비스 토큰에는 사용자 ID가 없으므로 현재 API 호출 권한이 없다.

## 매물 공급 계약

후속 구현은 운영센터에서 검증·확정한 매물만 버전 단위로 내보내는 전용 서버 API를 만든다. 브라우저가 상대 사이트의 관리 API를 호출하거나 D1을 공유하지 않는다.

예정 엔드포인트: GET /api/integration/v1/snapshots/latest. 응답 필드: schemaVersion=1, datasetVersion(불변 UUID), sourceDate, sourceFile, collectedAt(KST 원문 시각의 ISO UTC), publishedAt, checksum(SHA-256), completeSnapshot=true, district=마포구, counts, listings.

listings의 필드: sourceId(네이버 ID 또는 null), trackable, name, district, dong, type, deal, priceOptions[{price,rent}], sourcePriceText, priceText, area, floor, sourceUrl|null, sourceRow. 모든 금액은 만원 단위이며 범위의 보증금·월세 조합을 재조합하거나 평균내지 않는다. 비추적 행은 datasetVersion+sourceRow로 해당 버전 안에서만 식별한다. sourceUrl은 확인된 HTTPS 네이버 원문만 허용한다. 이전 버전에만 있는 원문 ID는 미수집으로 처리하며 거래 종료로 단정하지 않는다.

전송 인증: 양쪽 서버의 비밀 저장소에 별도 키를 설정하고 요청 본문 해시·시각·nonce를 HMAC-SHA256으로 서명한다. 고정 audience와 허용 origin, 5분 시각 허용오차, nonce 재사용 방지, rate limit, 키 회전 및 감사 로그를 적용한다. Sites 비공개 접근 경계를 통과할 지원 서비스 인증도 별도로 확인해야 한다. 현재 서비스 연동은 설정하지 않았다.

## 사용자 사이트에서 필요한 변경 — 착수 전 범위 설명 필요

1. 사용자별 JSON 안의 매물 복제를 공통 read-only 매물 버전 참조로 분리한다. 기존 조건·읽음 상태를 보존하는 마이그레이션을 추가한다.
2. 서버 전용 동기화가 위 계약을 검증하고 새 버전을 임시 저장한 뒤 원자적으로 활성화한다. 실패 시 마지막 정상 버전을 유지한다. datasetVersion으로 재실행을 멱등하게 만든다.
3. 사용자 데이터의 조건·알림 권한은 해당 사용자로 유지한다. 운영자에게 공유할 조건은 별도 동의 및 익명 exchangeCustomerId 매핑을 설계한다. 이메일이나 서로 다른 사이트의 userId로 자동 결합하지 않는다.
4. 실제 고객 조건 연동은 snapshot와 별도로 ruleVersion 및 enabled를 포함한 서버 API로 구현한다. 동의 철회/조건 비활성화를 반영한다. 현재 운영자가 입력한 조건은 고객 조건으로 자동 승격하지 않는다.
5. 사용자 사이트의 기존 공개 범위와 사용자 API의 운영 작업 차단을 유지한다. 관리 쓰기 API를 사용자 브라우저에 노출하지 않는다.

## 매칭과 외부 발송

서버 매칭 기준은 동·유형·거래·면적과 하나의 원문 priceOption이 보증금/월세 조건을 동시에 만족하는지다. 추적 불가 행은 보기용 매칭에는 포함하되 자동 가격 비교·알림에서 제외한다.

후속 알림 식별자는 datasetVersion+exchangeCustomerId+ruleId+sourceId+eventKind의 고유키로 중복 방지한다. outbox 상태는 generated, queued, sent, failed로 분리한다. 공급자의 실제 성공 응답이 있어야 sent로 전환한다. 재시도는 멱등 키와 횟수 제한을 쓴다. 수신 동의, 발송 채널, 자격 증명이 정해지기 전에는 generated에서 멈춘다. 현재 UI의 모든 알림은 운영센터 내부 생성이며 미발송이다.

## 하루 한 번 갱신

아직 스케줄을 등록하지 않았다. 자동으로 읽을 파일 위치, 해당 위치의 무인 접근, 갱신 시각(Asia/Seoul), 실제 수집 범위의 완전성, 중복 실행 잠금을 먼저 정해야 한다. 이후 파일 해시·파서 검증·버전 발행·사용자 사이트 동기화·outbox를 순서대로 실행하고 실패 시 기존 정상 자료를 유지한다. 테스트 기준은 같은 파일 재실행, 중간 실패 복구, 오래된 파일, 범위 누락, 동시에 실행된 작업이다.
